# CTech Poker CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a cross-platform terminal client (`poker`) that authenticates via OAuth PKCE or an API key and plays one CTech Poker sandbox table end to end.

**Architecture:** New Go module at `cli/`, separate from `api/`, sharing only the `.proto` source. `cobra` command surface; `bubbletea` full-screen TUI for the table and lobby prompts; a typed REST client for `/rooms` and `/players`; a `coder/websocket` table client speaking binary protobuf `ClientMessage`/`ServerMessage`. The server stays authoritative — the CLI renders snapshots and sends actions, holding no game logic beyond snapshot-diff narration and hand-strength labelling.

**Tech Stack:** Go 1.27, `github.com/spf13/cobra`, `github.com/charmbracelet/bubbletea` v1, `github.com/charmbracelet/lipgloss` v1, `github.com/charmbracelet/bubbles` v1, `github.com/coder/websocket` v1.8, `google.golang.org/protobuf`, `github.com/atotto/clipboard`, `github.com/charmbracelet/x/exp/teatest` (tests).

**Spec:** `docs/specs/2026-09-05-poker-cli.md`

## Global Constraints

- **Module path:** `gopkg.aoctech.app/poker/cli`. Go directive `go 1.27`. Never import `gopkg.aoctech.app/poker/api`.
- **Wire format on the table socket:** binary protobuf, 32 KiB max frame. Access token sent as the first frame after upgrade.
- **Player identity** is always the JWT `sub` server-side — never send a client-supplied player id in any payload.
- **Currency rendering:** `R$ <n>` only when the room's `currency_mode == "real"`. Sandbox renders the bare integer, no symbol, no "fichas" label.
- **Card colours:** hearts red, diamonds blue, clubs green, spades bright-white/bold. `--cards=ascii` or `NO_COLOR` env → `Ah Kd 7c Qs`, no colour. Never single-glyph playing cards (🂡).
- **Credentials file** `~/.config/ctech-poker/credentials.json` is mode `0600`, its directory `0700`. A corrupt file reads as "logged out", never a fatal error.
- **Commands** are `/`-prefixed inside the TUI. Hand every mutation an `idempotency_key` / `action_id` (UUID) that is *reused* verbatim on any retry of the same user intent.
- **Config precedence:** flag > env (`CTECH_POKER_*`) > `config.toml` > built-in default. API base default `https://poker-api.aoctech.app`, account base default `https://account.aoctech.app`, `client_id` default `poker-cli` (all overridable; confirm real hostnames during Task 1).
- **TDD:** every task is failing-test-first. `go test ./... -race` green before every commit. Conventional-commit messages, no `Co-Authored-By` trailer.
- **Docs:** update `cli/README.md` + `cli/CLAUDE.md` in the task that changes the behaviour they describe (repo mandatory-documentation policy).

```go
// Package config resolves CLI settings from defaults, an optional TOML file,
// environment variables, and explicit flags (lowest to highest precedence).
package config

import (
	"errors"
	"io/fs"
	"os"
	"path/filepath"

	"github.com/BurntSushi/toml"
)

const (
	defaultAPIBaseURL     = "https://poker-api.aoctech.app"     // confirm during Task 1
	defaultAccountBaseURL = "https://account.aoctech.app"       // confirm during Task 1
	defaultClientID       = "poker-cli"
)

type Settings struct {
	APIBaseURL     string
	AccountBaseURL string
	ClientID       string
	CardMode       string
	ConfigDir      string
}

type Flags struct {
	ConfigPath     string
	APIBaseURL     string
	AccountBaseURL string
	ClientID       string
	CardMode       string
}

type fileConfig struct {
	APIBaseURL     string `toml:"api_base_url"`
	AccountBaseURL string `toml:"account_base_url"`
	ClientID       string `toml:"client_id"`
	CardMode       string `toml:"card_mode"`
}

func defaultConfigDir() string {
	if x := os.Getenv("XDG_CONFIG_HOME"); x != "" {
		return filepath.Join(x, "ctech-poker")
	}
	home, _ := os.UserHomeDir()
	return filepath.Join(home, ".config", "ctech-poker")
}

func Load(f Flags) (Settings, error) {
	s := Settings{
		APIBaseURL:     defaultAPIBaseURL,
		AccountBaseURL: defaultAccountBaseURL,
		ClientID:       defaultClientID,
		CardMode:       "color",
		ConfigDir:      defaultConfigDir(),
	}

	path := f.ConfigPath
	if path == "" {
		path = filepath.Join(s.ConfigDir, "config.toml")
	}
	var fc fileConfig
	if _, err := toml.DecodeFile(path, &fc); err != nil && !errors.Is(err, fs.ErrNotExist) {
		return Settings{}, err
	}
	apply(&s.APIBaseURL, fc.APIBaseURL, os.Getenv("CTECH_POKER_API_URL"), f.APIBaseURL)
	apply(&s.AccountBaseURL, fc.AccountBaseURL, os.Getenv("CTECH_POKER_ACCOUNT_URL"), f.AccountBaseURL)
	apply(&s.ClientID, fc.ClientID, os.Getenv("CTECH_POKER_CLIENT_ID"), f.ClientID)
	apply(&s.CardMode, fc.CardMode, "", f.CardMode)
	if os.Getenv("NO_COLOR") != "" {
		s.CardMode = "ascii"
	}
	return s, nil
}

// apply sets *dst to the last non-empty value in order (each later arg wins).
func apply(dst *string, vals ...string) {
	for _, v := range vals {
		if v != "" {
			*dst = v
		}
	}
}

func CredentialsPath(s Settings) string { return filepath.Join(s.ConfigDir, "credentials.json") }
```

## Amendment (2026-09-05, mid-implementation): single interactive shell

After Tasks 1–11 were built exactly as planned, the user asked for a different
command surface (spec §10 amendment): `poker` with no arguments launches one
`bubbletea` program for the whole session — a login gate, then a `/command` home
REPL — instead of separate `poker login` / `poker profile` / `poker play`
subcommands.

**What changed from the plan as written:**
- Task 6's `poker login`/`poker logout` cobra commands (`cli/cmd/poker/login.go`)
  and Task 9's `poker profile`/`poker achievements` commands
  (`cli/cmd/poker/profile.go`, `deps.go`) were removed. The logic they wrapped
  (`auth.Session`, `rest.Client` calls, error-hint formatting) was kept and moved
  into `cli/internal/tui`.
- New: `cli/internal/tui/shell.go` (`Shell`, a `tea.Model`) — states
  `stateCheckingLogin → stateLoginChoice/stateAPIKeyInput → stateHome`, dispatching
  `/profile /achievements /play /enter /logout /help /exit` from one textinput
  prompt. `cli/internal/tui/format.go` holds the pure `FormatProfile`/
  `FormatAchievements` renderers (unit tested directly, no network).
- `cli/cmd/poker/main.go`'s root command now always runs
  `tea.NewProgram(tui.NewShell(cfg), tea.WithAltScreen()).Run()`; `--version` and
  the global config flags are unchanged. `bubbletea`/`lipgloss`/`bubbles` (Task 15's
  planned dependency) and `teatest` were pulled in now instead of at Task 15.
- Tasks 15–19 are **reduced in scope**, not removed: the lobby (Task 18) and table
  (Task 15–17) models still get built as `tea.Model`s and still render inside this
  same `Shell` — `/play` and `/enter` already exist as recognized home commands and
  currently answer "coming soon"; finishing Tasks 15–19 means wiring them to
  actually transition `Shell` into those models, not adding a new command surface.
  Task 19's `poker play` / `poker enter <room-id>` cobra commands are dropped —
  replaced by the `/play` and `/enter <id>` home commands already dispatching in
  `shell.go`.
- Task 21 (docs) must document the shell model, not a subcommand reference —
  already reflected in `cli/README.md`.

No task's file-level deliverables for auth/REST/websocket (Tasks 1–11) changed;
only the command-surface tasks (6, 9, 19, 21) and the spec's §10 did.
